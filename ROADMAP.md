# Roleplay Kernel — roadmap

Статус версии: см. `manifest.json` и `pyproject.toml` (`version`).

Правило поставки: каждая фаза завершается прогоном всех проверок, bump версии, commit и
push в GitHub. Установка в локальный SillyTavern делается только на контрольных точках,
перечисленных в разделе «Контрольные точки», а не после каждого промежуточного коммита.

Проверки, обязательные для каждой фазы:

```
ruff check .
mypy src tests
python -m unittest discover -s tests -q
node --check (копия index.js как .mjs)
node tests/js/panel-harness.mjs      # рендер панели в jsdom
node --test tests/js/*.test.mjs      # JS-регрессии
```

## v0.6.2 — Hotfix по итогам живой проверки  ✅ завершена

Третий баг, найденный при live-проверке нового `select_profile`:

`STProfileConfig.from_dict` требовал непустую строку в `api_url` и `secret_id`.
Расширение отправляет `api_url: String(profile['api-url'] || '')`, то есть
**пустую строку** для любого профиля без custom endpoint. Такой профиль ронял
разбор — и в `select_profile`, и в конверте генерации.

- `_config_string` получил `allow_empty`; пустое значение означает «resolve через
  ST», а не «ошибка формата».
- Валидация провайдера не ослаблена: `custom` без URL по-прежнему отвергается.
- `require_upstream_profile` добавлен в отчёт `diagnostics`, иначе его влияние на
  поведение не видно.

**Живая проверка после установки (ST, реальный файл сессии):**

- `status` по сессии, записанной старой версией → `exists=true`,
  `state_version=2`, `insights` на месте. Прежде было `400`.
- `select_profile` → `provider=STConnectionProfileProvider`.
- `self_test upstream_profile` → `ok=true`. Прежде был ложный `false`.
- `diagnostics.upstream.provider` → `STConnectionProfileProvider` вместо
  `OpenAICompatibleProvider` с `api.openai.com`.


## v0.6.1 — Исправления, найденные живой диагностикой  ✅ завершена

Обе ошибки найдены не в теории, а в отчёте `Copy diagnostics` из живого ST.

**1. Сессия, сохранённая до v0.4.0, становилась нечитаемой.**

`RoleplayState.from_dict` вызывал `_string_map(data.get("provenance"))`, а
`_string_map` требовал объект. У сессии, записанной старой версией, ключа
`provenance` просто нет → `ValueError` → `control/status` отдавал
`400 request data is invalid` → watchdog считал runtime мёртвым → маршрутизация
выключалась, аддон становился нерабочим. Хуже всего: сообщение не содержало
ничего полезного.

- `_string_map(None)` теперь означает «пусто», а не «повреждено».
- Регрессионные тесты на сессии без `provenance`, `elapsed_hint`,
  `module_reasons`, `superseded` — и на чтение такого файла свежим runtime.
- `except ValueError` в HTTP-обработчике теперь печатает трейсбек в stderr:
  ошибка без следа больше невозможна.

**2. Профиль ST не применялся до первого хода, self-test давал ложный отказ.**

`_apply_upstream_profile` вызывался только внутри `generate()`. До первого
хода sidecar держал прямой провайдер из конфига, поэтому:

- `self_test` показывал `upstream_profile: False`, хотя профиль был выбран;
- `diagnostics` рапортовал `https://api.openai.com/v1` и `gpt-4o-mini` —
  то есть провайдера, которого у пользователя нет;
- запрос, пришедший без профиля в конверте, молча ушёл бы на этот API.

- Новое control-действие `select_profile` применяет профиль сразу; расширение
  вызывает его при активации, смене профиля и смене задержки.
- `require_upstream_profile` (включается серверным плагином) запрещает ход без
  профиля: `409 upstream_profile_required` вместо отправки текста наружу.
- Автономный режим sidecar с прямым `upstream_base_url` не затронут — флаг
  выставляется только плагином ST.


**Установлено в ST:** v0.6.0. Проверено на живой копии:

- Развёрнутые файлы совпадают с репозиторием, `manifest.json` и `index.js` → `0.6.0`.
- Установленный venv-пакет содержит `superseded` и `provenance`.
- `/health` → `0.6.0`, есть `metrics`.
- `diagnostics` → версия и бюджеты на месте.
- `self_test` → честно сообщает `upstream_profile: False`, пока не выбран профиль ST.
- Защита `Host` → `421` на не-loopback заголовке.
- Стриминг render-этапа подтверждён по реальному HTTP с подставным upstream:
  `text/event-stream`, 10 инкрементальных кадров, текст собирается точно,
  первый токен на 0.53s, один вызов провайдера в режиме `Lite`.
- Миграция конфига добавила `turn_budget_seconds` и `post_render_grace_seconds`,
  сохранив ключ и upstream пользователя.

**Важно для апгрейда:** старый runtime может продолжать держать порт после
обновления. Расхождение версий ловит handshake в extension — он покажет
предупреждение «extension 0.6.0 but sidecar 0.1.1». Лечится кнопкой
`Restart runtime` или перезапуском ST.

**Состояние ST после контрольной точки:** маршрутизация выключена,
`custom_url` и `custom_model` восстановлены из профиля пользователя,
`custom_include_headers` пуст.

## Перенесено за пределы MVP

- Structure-aware антиповтор с отслеживанием образов: текущий n-граммный
  контроль покрывает основное, а семантический требует эмбеддингов.
- Массовое подтверждение низкорисковых операций: требует понятного diff из v0.6.0.

## Отложено сознательно

- Векторный кэш и семантическая дедупликация: низкая отдача для ролёвки, высокая цена.
- Семантический поиск по памяти: зависит от модели и провайдера, отложено до v0.7.
- Полноценный SSE в ST для всех этапов: сначала нужен измеряемый baseline v0.2.0.
