# Roleplay Kernel — план оптимизации качества

## Цель

Максимальное понимание контекста, свежие ответы без повторов, эха и клише,
отсутствие деградации прозы. Всё настраивается под разные бюджеты токенов и
запросов. Развитие агентного подхода с измеримым результатом.

## Принцип

Сейчас все стадии используют одну модель и один контекст. Нужна
**дифференциация по задаче и по содержанию**:

- Разные модели для разных задач (не тратить дорогую модель на извлечение фактов)
- Разный контекст для разных задач (релевантность, а не просто давность)
- Разные ограничения качества для разных задач (анти-клише для прозы, точность для состояния)

## Фаза 1 — ProfileRouter (v0.7.0)

**Проблема:** одна модель на все стадии. Извлечение фактов и суммаризация — 80%
вызовов, и они не нуждаются в дорогой модели.

**Решение:** `ProfileRouter` маршрутизирует вызовы по стадиям:

| Стадия | Задача | Рекомендуемый профиль |
|---|---|---|
| `render` | творческая проза | дорогая модель, высокая креативность |
| `extract` | извлечение фактов | дешёвая модель, точность |
| `critic` | проверка качества | средняя модель, анализ |
| `repair` | исправление прозы | та же, что render |
| `plan` | планирование сцены | средняя модель, стратегия |

**API:**

```python
class Stage(str, Enum):
    PLAN = "plan"
    RENDER = "render"
    EXTRACT = "extract"
    CRITIC = "critic"
    REPAIR = "repair"

@dataclass(frozen=True)
class ModelProfile:
    name: str
    provider_factory: Callable[[], ChatProvider]
    max_output_tokens: int | None = None
    temperature: float | None = None

class ProfileRouter:
    def provider_for(self, stage: Stage) -> ChatProvider: ...
    def describe(self) -> dict[str, str]: ...
```

**Конфиг (config.json):**

```json
{
  "stage_profiles": {
    "render": "creative",
    "extract": "fast",
    "critic": "balanced",
    "repair": "creative",
    "planner": "balanced"
  },
  "model_profiles": {
    "creative": {"base_url": "...", "model": "...", "api_key_env": "..."},
    "fast": {"base_url": "...", "model": "...", "api_key_env": "..."},
    "balanced": {"base_url": "...", "model": "...", "api_key_env": "..."}
  }
}
```

По умолчанию все стадии используют основной провайдер (обратная совместимость).

**Изменения:**
- `Engine.__init__` принимает `router: ProfileRouter | None`
- `Engine._complete` использует `router.provider_for(stage)` вместо `self.provider`
- `SessionService` создаёт router из конфига
- Installer добавляет секцию `stage_profiles` в config.json

**Тесты:**
- Разные стадии идут через разные провайдеры
- Неизвестная стадия → fallback на дефолтный профиль
- Профиль без явной модели использует основной провайдер

## Фаза 2 — StyleTracker + анти-клише (v0.8.0)

**Проблема:** повторы начал фраз, одни и те же описания, падение в клише.

**Решение:** `StyleTracker` отслеживает:
- Начальные фразы последних N ответов
- Использованные семантические блоки (события, описания, эмоции)
- Паттерны предложений (длина, структура)

Критик получает это как ограничение: «не используй эти начала, не повторяй эти
смыслы».

**Данные:**
```python
@dataclass
class StyleTracker:
    recent_openings: list[str]       # первые 20 символов
    used_semantics: set[str]         # ключи описаний
    used_patterns: set[str]         # структурные паттерны
```

**Изменения:**
- `SessionService` хранит `StyleTracker` на сессию
- `Engine._evaluate_candidate` передаёт tracker в критик
- `compiler.compile_critic` добавляет `STYLE_CONSTRAINTS`
- После рендера tracker обновляется

## Фаза 3 — Скоринг релевантности (v0.9.0)

**Проблема:** компилятор конкатенирует всё подряд; далёкие факты размывают важные.

**Решение:** скоринг релевантности в `ContextCompiler`:
- Вес свежести (недавнее важнее)
- Вес связности с текущим ходом (упоминания персонажей, локаций)
- Отсечение по порогу (signal-to-noise)

**Метрика:**
```python
relevance = 0.4 * recency + 0.3 * entity_overlap + 0.2 * causal_link + 0.1 * emotional_salience
```

## Фаза 4 — Суммаризация транскрипта (v0.10.0)

**Проблема:** длинный транскрипт перегружает контекст.

**Решение:** скользящее окно с суммаризацией:
- Последних N ходов — дословно
- Остальное — в сжатом виде
- Скрытие после M ответов или вручную

---

## Фаза 5 — Расширенные бюджеты (v0.11.0)

**Проблема:** единый `turn_budget` на все стадии.

**Решение:** бюджеты по стадиям:
- `render_budget_seconds`
- `post_render_budget_seconds`
- `max_extract_tokens`
- `max_critic_tokens`
